## 2026-08-31 - Project devlog workflow established

**Result**

- The repository gained a monthly, newest-first development log, a safe search
  helper, a project-local `project-devlog` skill, and a discoverable README and
  repository-policy entrypoint.
- The initial August log backfills eight durable milestones from the public
  repository's creation through the native GitHub review-thread contract.

**Why / context**

- Commit and pull-request history retain delivery detail, but they do not offer

  keeps the same signal, append-only, and public/privacy boundaries.

  the focused suite passed after the repair.
- `npm test` passed 72 tests with 10 environment-dependent exact-runtime tests
  skipped, and the manifest-only compatibility check confirmed the locked
  runtime-kit and DSH identities.
- Package reproducibility passed, and `npm pack --dry-run` included both devlog
  documents in the coordinated public artifact.
- Public commit and pull-request history through commit `fe9a249` was reviewed

## 2026-08-31 - Native review threads made mandatory

**Result**

- Coordinated release 0.3.0 requires every actionable GitHub review finding to
  carry a stable fingerprint and map one-to-one to a native review thread at an
  exact file or line location.
- Non-actionable findings remain report-only, while duplicate, missing, extra,
  false-mapped, and location-mismatched threads fail closed.

**Why / context**

- A prose-only review report cannot prove that each owner-actionable finding is
  independently discussable and resolvable on the provider. The native-thread
  contract makes that relationship explicit without treating threads as
  authority or credentials.

**Evidence**

- PR #15 added the fingerprinted worker-result schema, mixed-output success
  coverage, negative mapping cases, and exact publisher/profile compatibility
  checks before advancing the coordinated catalog to 0.3.0.

## 2026-08-30 - Governed GitHub review plugins added

## 2026-08-29 - Governed application runtime established

**Result**

- The public plugin SDK, generic ten-operation application manager, and exact
  DSH rc.2 adapter established the reusable application runtime layer.
- The manager delegates composition, admission, lifecycle, isolation, and
  mediated effects to runtime-kit while the adapter confines DSH tools and
  preserves per-instance cleanup and concurrency boundaries.

**Why / context**

- dsh-applications needs a portable application surface without forking DSH or
  duplicating runtime-kit policy. The package split makes descriptor creation,
  lifecycle orchestration, and version-specific DSH adaptation explicit and
  independently testable.

**Evidence**

  sandbox, integration, exact-consumer, type, and packaging coverage, including
  review-driven closure of admission, teardown, and descriptor-literal gaps.
